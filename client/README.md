# 桌面客户端

这个目录把 AI 小说生成器打包成 Windows 独立窗口程序。用户不需要安装 Python、Node 或 Docker，双击 exe 就能使用。

客户端启动和打包代码放在 `client/`；对应的导入、日常续写、章节概要、本书大纲、模型选择和多轮自审功能同时修改了前后端。`frontend/next.config.ts` 通过 `NEXT_OUTPUT` 环境变量开启 standalone 构建，网页版仍可正常启动。

## 常用操作

| 要做什么 | 怎么做 |
|---|---|
| 打包 | 双击 `build.bat`，产物在 `dist\AI小说生成器\`；同时在桌面创建或更新快捷方式（加 `--no-shortcut` 可跳过） |
| 只改了后端或客户端代码，重新打包 | `build.bat --skip-frontend`（几秒完成，复用上次的前端构建） |
| 边改边看效果 | 双击 `dev.bat`，直接运行仓库源码（见下文） |
| 运行测试 | 双击 `tests.bat`（见下文“测试”） |
| 改窗口大小、端口、数据目录 | 编辑 `client.toml` |
| 升级 Python / Node / MongoDB | 编辑 `versions.toml` 后重新打包 |
| 分发给别人 | 把整个 `dist\AI小说生成器\` 文件夹压缩发出去（注意 AGPL-3.0 许可证：分发修改版需要同时提供源码） |

## 开发模式（dev.bat）

- 前端以 `next dev` 运行。改了 `frontend/src` 下的代码，在窗口里按 **F5** 刷新就能看到效果。
- 后端直接运行仓库里的 `backend/`。改了后端代码，需要关闭窗口再重新运行 dev.bat。
- 开发模式的数据保存在 `client\build\dev-data`，和正式版的数据分开。
- 第一次运行会自动下载运行环境，之后不再重复下载。

如果想用浏览器开发者工具，把 `client.toml` 中的 `debug` 设为 `true`，然后在窗口内右键选择“检查”。

## 结构

```
client/
├─ client.toml          客户端设置（窗口、端口、数据目录）
├─ versions.toml        打包使用的运行环境版本
├─ requirements-client.txt  客户端额外的 Python 依赖
├─ build.py / build.bat 打包脚本
├─ dev.bat              开发模式
├─ tests.bat / run_tests.py  运行测试
├─ tests/               测试代码
├─ launch.py            入口（exe 和 dev.bat 都执行它）
├─ launcher/Launcher.cs exe 启动器源码，只负责调用 launch.py，一般不需要修改
└─ novel_client/
   ├─ app.py            窗口、启动页、错误页、启动和关闭流程
   ├─ services.py       MongoDB / 后端 / 前端三个子进程
   ├─ config.py         路径和配置（开发模式与打包模式的区别都在这里）
   ├─ run_backend.py    在子进程中运行原项目的 main.py
   └─ winjob.py         保证客户端退出时所有子进程一起退出
```

打包产物：

```
dist\AI小说生成器\
├─ AI小说生成器.exe
├─ app\        后端源码（原样复制，打包后也可以直接修改 .py 文件，重启生效）
├─ frontend\   前端 standalone 构建
├─ runtime\    python / node / mongodb
└─ client\     客户端代码和 client.toml
```

用户数据（小说数据库、模型配置、日志）保存在 `%LOCALAPPDATA%\AINovelGenerator`，不放在程序目录里。所以重新打包或替换程序文件夹都不会丢失数据。

模型供应商及 API 密钥保存在该目录下的 `user_data\config\config.yaml`。更新前会校验配置备份，备份放在 `user_data\backups\settings`，相同内容只备份一次。旧版位于程序目录中的配置会先复制到用户目录；已有用户配置不会被默认配置覆盖，不同的旧副本会分别备份。备份失败时更新会停止。

重新打包保留产物中已有的 `client\client.toml`，因此自定义数据库名和数据目录也会保留。软件运行时，或自定义数据位于即将替换的程序目录内时，会停止更新以防误删。开发模式仍使用独立数据目录。分发的新程序不包含开发者的供应商配置和密钥。

## 启动流程

1. exe 用内置 Python 运行 `client\launch.py`。
2. 窗口显示启动页，后台依次执行：
   - 启动 `mongod`。首次运行时自动初始化单节点副本集 `rs0`，因为后端保存数据需要事务。
   - 并行启动后端（`main.py`）和前端（`node server.js`）。
3. 两个服务都就绪后，窗口加载界面。
4. 关闭窗口时按 前端 → 后端 → 数据库 的顺序停止服务，数据库会正常关闭以确保数据写盘。即使客户端崩溃，Windows 作业对象也会结束所有子进程。

数据库连接通过环境变量传给后端，所以首次使用**不需要**再到“设置 → 数据库配置”里填写连接，只需要配置模型 API。

启动失败时，窗口会显示出错的服务和日志末尾。完整日志在 `%LOCALAPPDATA%\AINovelGenerator\client_logs\`。

## 多轮自审写作

写本章正文时，默认方案是“本章正文（多轮自审）”。它在原有流程生成正文之后，增加了一个“多轮自审”节点：

1. 审查正文，打分（1–10）并列出问题，每条问题附原句和修改建议。
2. 不合格时，按问题修改正文，然后再审查。
3. 合格就停止；一直不合格时，修改满设定轮数后再做一次确认审查，然后停止，剩下的问题交给你审阅。

合格的条件是：审查判定通过、分数达到合格线（默认 8 分），并且没有“必须修改”级别的问题。

**轮数和深度**：生成表单里的“自审轮数”控制最多修改几轮，同时决定审查有多细。

| 轮数 | 深度 | 审查范围 |
|---|---|---|
| 0 | 不审查 | 与原方案相同 |
| 1 | 轻度 | 只查硬伤：与设定或前文矛盾、违背本章计划、人物用了不该知道的信息、成段的 AI 腔 |
| 2 | 中度 | 硬伤，加上节奏、对白生硬、人物声音雷同、重复用词和套话 |
| 3 及以上 | 深度 | 逐段精读，包括措辞、句式、细节、情绪层次和章末钩子 |

每轮最多 2 次模型调用（审查、修改），最后可能再加 1 次确认审查。2 轮时最多 5 次，费用和耗时约为原方案的 3–5 倍。

**审查方面**：内置四项，分别是去 AI 腔与文笔、设定与前文一致性、情节与节奏、对白与人物声音。增加新要求有两种方式：

- **长期生效**：打开“任务流程”页面，编辑“本章正文（多轮自审）”方案，选中“多轮自审”节点，点“添加审查方面”，填写名称和检查内容后保存。已有的审查方面可以修改、停用或删除。
- **只对这一次有效**：在生成表单的“本次额外审查要求”里填写。

**切换回原方案**：在“任务流程”页面把“本章正文（局部资料）”设为默认即可。软件只会在首次启动时自动切换一次，之后不会改动你的选择。

**查看审查记录**：生成过程中，“多轮自审”这一步会显示每轮的分数和问题数量。完成后展开它的原始输出，`review_log` 里有每轮的问题清单和停止原因。

相关代码：`backend/services/task_flows/review_loop.py`（循环逻辑）、`review_prompts/`（审查和修改提示词）、`self_review_flow.py`（方案的生成与安装）。原项目的内置正文流程文件没有改动。

## 导入已有小说

书架页点“新建小说”，切到“导入文件”页签：

1. 点击多选电脑里的 `.txt`、`.md`、`.markdown` 或 `.docx` 文件，或在“导入文件”页签打开时一次拖入多个文件（合计不超过 30 MB，一次最多 1000 个文件、5000 章）。可以继续选择或拖入以追加文件。
2. 单个整书文件默认自动识别编码（UTF-8、GBK 等）和卷、章标题。多个章节文件默认“每个文件一章”：采用文档开头的章节标题，没有则用文件名；文件内的正文不会按默认字数误拆成多章。长章节也会完整保留。
3. 文件列表按章号或文件名排序（支持中文章号和 1、2、10 这样的数字顺序），可上下调整和移除。填写整本小说的书名，确认预览；也可切换自动识别、自定义正则、按字数切分或所有文件合为一章。
4. 点“开始导入”。整本书在一个事务里写入，中途出错不会留下半本书；重复点击不会导入两本。

识别规则：`第X章/节/回/话`、`第X卷/部/集/篇`、`序章/楔子/番外/尾声`、`Chapter N`，没有这些写法时退回 Markdown 的 `#` 标题；都没有就按字数切分并提示。开头的目录页会被忽略，长章节不会被自动拆分，文件开头的书名和简介保存为小说简介。所有这些调整都会在识别结果里以提示的形式告诉你，文字本身一个都不会丢。

导入后的小说和手工创建的完全一样：可以阅读、修改，每章都有历史版本（导入时的原文是第一个版本）。需要知道的限制：

- 每一卷下面只有一个“导入的正文”篇章和一个场景，章节都放在里面。软件不会替你编造原稿里没有的篇章结构。
- 卷的目标、前提等规划写的是“（导入的正文，尚未整理）”这样的占位说明，之后可以在卷页面修改。
- 导入不会自动提取人物、势力等设定。日常续写不要求这些资料，需要时可以从前文 AI 整理人物设定备忘。

相关代码：`backend/services/novel/import_parser.py`（解析）、`import_service.py`（写库）、`backend/api/default_routers/novel_import_router.py`（接口）、`frontend/src/components/bookshelf/ImportPanel.tsx`（界面）。

## 日常续写

打开已有小说后，默认进入“小说续写”：关联前文 → 填后续剧情大纲 → 生成并编辑正文 → 保存为下一章。

- 默认关联最近 3 个有正文的章节，可以调整选择。原文按阅读顺序完整发送，最多选择 100 章，不设文本字数上限。
- 每章都有独立概要。在关联列表中，每一章分别二选一“正文／概要”，例如第一章用概要、第二章用正文。选择概要时只发送该章已保存的概要，不附带该章正文。没有概要会先提示，确认后进入概要小窗，选择模型生成或手写，保存并返回续写页。章节编辑器也可打开同一个概要小窗；保存概要不会改写正文。
- 概要按实际剧情顺序写成连贯的自然段，不使用“起因／经过／结果”式提纲。概要、正文、大纲和创作要求不设软件字数上限；目标字数可以留空。上游模型自身的上下文和输出容量仍适用。
- 模型独立返回的思考字段以及 `<think>`、`<thinking>`、`<analysis>`、`<reasoning>` 思考块会过滤，不进入稿件；正常英文内容保留。
- 日常创作也会在流式展示前过滤开头类似“I need to write a Chinese summary”的英文工作说明。概要小窗提供“清空概要”，清空后可直接重新生成；点击“保存并返回”才会更新已保存概要，也支持保存为空。保存为空时，仅该章的概要关联会切回正文。
- 章节概要先在后台完整接收并校验，再显示中文成品，等待时显示整理进度。上游返回整段英文计划或不完整的成品时不会填入编辑框；语言或成品校验不通过时，沿用所选供应商和模型再生成一次，仍不合格则提示失败并保留原草稿。
- 人物设定放在可选区域，点击“AI 生成人物设定”即可根据前文和大纲整理为可编辑备忘。备忘随本书续写草稿保留，续写时一并使用；它不自动覆盖正式人物卡。
- 续写、人物整理、章节概要、本书大纲和高级 AI 生成表单可选择供应商及同一 API 下的其他模型，也可手填模型 ID；不选择则沿用默认配置。正文流式显示，可停止。输入、生成文字及待核对的保存命令保留为本地草稿，也可导出。
- 在设置中获取上游模型会保存完整目录，无须逐个添加。保存设置后，所有 AI 入口均能切换目录内的任意模型；自定义显示名称与完整目录独立保留。
- 日常正文生成默认最多修改 2 轮：生成后审查，发现问题则修改并再次审查；达到上限后停止并保留审查记录，不保证模型判断始终正确。展开“正文自主审查与修改”可设为 0 关闭，或调整到 1–5 轮并填写额外要求。审查及修改使用本次正文所选模型，额外调用会增加耗时和用量。
- 确认保存时追加到本书末尾，复用章节版本、历史和字数统计。自动建立所需目录，无须先填写设定卡或各级规划。书尾或前文变更时要求核对，断线重试不会重复创建章节。
- 原来的“小说信息”编辑页改为“本书大纲”，每本书单独保存。可以创建空白大纲、导入 `.txt`／`.md`／`.markdown`／`.docx`、编辑保存，也可根据当前大纲及后续要求生成候选并追加到草稿，确认保存后生效。“人设”和“章节编辑”直接放在主导航；其他资料和分卷、篇章规划保留在折叠的高级区域。

相关代码：`backend/services/novel/continuation_service.py`、`backend/api/default_routers/continuation_router.py`、`frontend/src/components/writing/ContinuationWorkspace.tsx`。

## 模型供应商保存与数据库设置

桌面启动器会自动提供本地数据库连接。设置页显示实际数据库名称，并注明由启动器管理，保存模型供应商不要求手动填写数据库名称，也不会把运行时端口或库名写回配置文件。

只修改模型设置时，保存请求只提交模型字段。未修改的空数据库字段不会阻止保存；手动修改数据库配置时仍会校验名称和连接超时。数据库已有小说时保留原库名，不通过切换库名解决模型保存错误。

每个供应商可以“获取上游模型”，为模型设置自定义显示名称并保存多个模型。显示名称仅用于界面，实际请求使用对应的模型 ID。获取列表使用已保存的密钥；如果上游没有提供模型列表接口，可以继续手动添加模型，不必为同一 API 重复建立供应商。

## 启动速度

后端启动曾经要十几秒，大部分时间花在同时加载三个模型厂商的官方 SDK（anthropic、openai、google-genai）上，而它们只在真正调用模型时才需要。现在按需加载：启动时不再加载，第一次用到某个厂商时才加载它（约几秒，只发生一次）。数据库、后端、前端也改为同时启动，数据库的启动时间被后端加载的时间盖住。打包时还保留了运行环境自带的字节码缓存，重新打包后的第一次启动不再需要重新编译。

## 窗口内导航

桌面窗口启用文字选择，可选中正文、提示和报错后按 Ctrl+C 复制。设置页的接口测试结果还提供“复制报错／复制结果”按钮；复制权限不可用时会尝试兼容方式，并保留可手动复制的文字框。

Claude 的第三项测试检查结构化输出。若接口返回 Markdown 围栏包裹的 JSON，会明确提示未遵守原生 JSON Schema；如果工具调用测试通过，可以在“结构化输出方式”里尝试“工具输出（旧模型）”并重新测试。该模式是否可用仍以实际测试为准。

设置页的“配置流程”按钮用 `window.open` 打开流程编辑器，pywebview 默认会把所有新窗口请求交给系统浏览器。`novel_client/navigation.py` 改为：本应用自己的地址在当前窗口打开，用户主动点击的外部网页链接（如官方文档）用系统浏览器；本地文件和自动弹窗不交给浏览器，并阻止本地文件替换应用页面。前端整页拦截文件拖放的默认导航，“导入文件”页签可见时接收文件并预览，其他页签只阻止默认打开。从编辑器点“返回”会回到设置页；如果你在设置页有尚未保存的修改，进入编辑器前请先保存。

## 排查界面问题

本书大纲采用独立的章纲目录，每章分别读取、编辑、留稿和保存，不限制创作字数。大纲页接收整个窗口拖入的 TXT、Markdown、Word（.docx）文件，支持多选、调整文件顺序、按章标题识别或每文件一章；先预览，再确认追加，不覆盖原有章纲。没有章标题的文件完整保留为一条，可逐章手动整理。单批上传与正文一致为 30 MB、1000 个文件，可分批持续追加。目录分页展示，不把整本大纲放进一个编辑器。

首次打开会按标题迁移原有 `novel.plot` 大纲，事务防止重复迁移，原字段保留作备份；旧版未保存的本地大纲草稿也提供恢复入口。AI 后续大纲只引用勾选的章纲，候选经确认后按章追加。单书归档 v15 包含独立章纲和导入回执，并保留旧版恢复索引。

`tools/cdp.py` 和 `tools/stack.py` 可以用无头 Edge 操作打包产物里的真实页面，并收集脚本错误，界面测试（`tests/test_ui.py`）就是用它们写的。界面出现白屏或报错时，按 `test_ui.py` 的写法复现，页面的报错信息会出现在 `page.console` 里。注意要先关闭正在运行的客户端，因为后端端口只有一个。

## 测试

双击 `tests.bat` 运行全部测试，约 1.5 分钟。只跑某一组时，在命令行执行 `build\runtime\python\python.exe run_tests.py tests.test_app`。

| 文件 | 测试内容 |
|---|---|
| `test_config.py` | 读取 client.toml；开发模式和打包模式的路径；打包后后端端口以 packaged.json 为准 |
| `test_persistence.py` | 旧供应商和密钥迁移、去重备份、不同副本保留；真实 API 保存后切换程序目录重启，供应商、密钥及小说保持可读 |
| `test_winjob.py` | 客户端退出时，子进程和孙进程都会被结束 |

## 扩展示例

**新增一个后台服务**：在 `services.py` 中继承 `Service`，实现 `command()` 和 `is_ready()`，然后在 `app.py` 的 `build_services()` 和 `_start_services()` 中加入这个服务。

**网页调用本地功能**（例如打开文件夹）：在 `app.py` 的 `Api` 类中加一个方法，前端就可以通过 `window.pywebview.api.方法名()` 调用。现有的例子是 `open_logs()` 和 `open_data_dir()`。

**新增 Python 依赖**：后端依赖写进项目根目录的 `requirements.txt`，客户端依赖写进 `requirements-client.txt`。打包时会自动检测变化并重新安装。

## 默认端口

客户端使用 27117 / 18200 / 13300，和网页版的 27017 / 8200 / 3300 错开，两者可以同时运行。修改后端端口后必须完整重新打包，因为前端代码里写死了后端地址。
